# Cetacean audio models and sound-to-form experiments

For the main comparison tables, start with the [model guide](models.md).
This report retains the detailed source audit and generation workflow notes.

Verified against public model cards, code, configurations and release metadata on **2026-10-04**. This is a source audit, not an inference benchmark: no weights were downloaded and no model was run.

The strongest initial artwork is a transparent mapping from acoustic structure to visual structure. Neural embeddings can add another layer of variation, but neither an embedding nor a generated coda establishes what an animal is communicating.

## Model comparison

| Model | Released capability | Exact input / representation | Useful role | License / practical caveat |
|---|---|---|---|---|
| **WhAM** | Sperm-whale coda generation, audio style transfer and embeddings | Published pipeline uses **16 kHz**, 10-second tokenizer input; VampNet/DAC masked acoustic tokens. Embedding wrapper also starts at 16 kHz. | Generate synthetic coda variations; compare click rhythm and spectral texture. | Code MIT; **published Zenodo weights CC BY-NC-ND 4.0**. Full annotated evaluation corpus is only partly public. |
| **DoLittle MMC** | Humpback-song continuation from tokenized audio prompts | **44,100 Hz DAC**, nine codebooks, 512-sample hop; autoregressive decoder with MoE. | Continue a song fragment; explore temporal organization and synthetic variations. | Released weights/configs/docs Apache-2.0; token corpus has separate custom terms and source attribution. |
| **OpenWhistle Wav2Vec2.0** | Dolphin-whistle representations, not audio generation | **Mono 44,100 Hz**, normalized waveform; 768 hidden dimensions, 12 transformer layers, 8 heads. | Whistle similarity, clustering, temporal embedding trajectories and supervised fine-tuning. | Model card explicitly says license unspecified; needs a downstream head for classification/detection. |
| **LAION CLAP** | Audio/text embeddings, text-to-audio retrieval and zero-shot candidate scoring | Audited `laion/clap-htsat-unfused`: **48,000 Hz**, 10-second windows, **50–14,000 Hz mel range**, 512-dimensional projected embeddings. | Audible texture and user-defined descriptive vocabulary; inexpensive baseline against specialist encoders. | This HF checkpoint is Apache-2.0; upstream LAION code LICENSE is CC0. General audio training is not evidence of cetacean semantics. |
| **BioLingual** | CLAP-style audio/text matching trained on bioacoustic data | Audited `davidrrobinson/BioLingual`: **48,000 Hz**, 10 seconds, **50–14,000 Hz mel range**, 512-dimensional projected embeddings. | Compare biological audio against general CLAP; species/call retrieval and exploratory descriptors. | HF model card does not specify a license. | **AVES / AVEX** | Audio representations, classification probes and fine-tuning | Original AVES: **16,000 Hz** mono; HuBERT-style encoder, 768 dimensions for base models. ## What WhAM and DoLittle actually let us control

**WhAM** generates pseudocodas and transfers acoustic characteristics of prompts into coda-like sound. Its embeddings were evaluated using separately trained classifier heads for coda detection, rhythm type, social unit and spectral categories called “vowels.” Those task labels are not decoded messages. The README explicitly warns that reproducing all results requires DSWP+CETI annotations that are only partly released; access to the small public DSWP audio pack does not provide all the reported social-unit labels. [Generation and evaluation release](https://github.com/Project-CETI/wham), [downstream tasks and labels](https://arxiv.org/html/2512.02206v1#A5.SS4).

WhAM's documented installation uses Python 3.9, editable VampNet and `madmom`, plus ffmpeg. The downloaded coarse, fine, codec and beat files total approximately **3.09 GB**. The browser example uses CUDA; the paper reports experiments on NVIDIA A10 hardware, which is not a demonstrated minimum VRAM requirement. Keep this legacy stack in an isolated uv environment and audit its paths/dependencies before inference. The weights license is materially different from the code license. [Install instructions](https://github.com/Project-CETI/wham#installation), [weight files and license](https://zenodo.org/api/records/17633708), [compute methods](https://arxiv.org/html/2512.02206v1#A5.SS3).

**DoLittle** provides three checkpoint families. Their context sizes count **interleaved codec tokens**, not seconds or individual whale calls:

| Checkpoint | Architecture | Context | Approximate audio context | `best_model.pt` size |
|---|---|---:|---:|---:|
| 10k | Sliding-window attention + MoE | 10,240 tokens | 13.2 seconds | 1.92 GB |
| 32k | Sliding-window attention + MoE | 32,768 tokens | 42.3 seconds | 1.50 GB |
| 128k | Compressed global attention + MoE | 131,072 tokens | 169 seconds | 1.50 GB |

Audio durations follow `context / (9 × 44100 / 512)`. These are total prompt-plus-continuation capacities; they do not promise uninterrupted meaningful song structure. Sizes are decimal GB from the public HF file API. [10k config](https://github.com/cairninstitute/cairn_marine_mammals_communication/blob/master/configs/audio_large_swa_moe_sanctsound_humpback_dac_9cb_10k.yaml), [32k config](https://github.com/cairninstitute/cairn_marine_mammals_communication/blob/master/configs/audio_medium_swa_moe_sanctsound_humpback_dac_9cb_32k.yaml), [128k config](https://github.com/cairninstitute/cairn_marine_mammals_communication/blob/master/configs/audio_medium_nsa_moe_sanctsound_humpback_dac_9cb_128k.yaml), [release files API](https://huggingface.co/api/models/cairninstitute/mmc-humpback-dac9-models?blobs=true).

The unified script accepts explicit `.npy` audio-token prompts, prompt offsets/duration, continuation duration, temperature and top-k. It defaults to CUDA and 4-second prompts; decoding loads DAC on CPU. It is not text-prompted and does not accept a raw WAV directly as the prompt argument. Supply a compatible token array or tokenize a recording with the provided DAC frontend. Ranked automatic prompt selection additionally uses `chunk_scores.csv`; an explicit prompt bypasses that ranking, so a first test need not fetch the entire 29-shard corpus. Dependencies include PyTorch/Torchaudio >=2.5 and Python >=3.10; verify the audio-codec extra's dependency resolution in a separate environment. Short generation can begin with one checkpoint and one prepared prompt; no local speed or VRAM benchmark has been established. [Generation script](https://github.com/cairninstitute/cairn_marine_mammals_communication/blob/master/scripts/generate_dac_9cb_unified.py), [dependencies](https://github.com/cairninstitute/cairn_marine_mammals_communication/blob/master/pyproject.toml), [dataset terms](https://huggingface.co/datasets/cairninstitute/mmc-sanctsound-humpback-dac9/blob/main/DATASET_TERMS.md).

## Preserve the frequencies before choosing an encoder

Resampling with antialiasing removes content above the new Nyquist limit: 8 kHz at 16 kHz input, 22.05 kHz at 44.1 kHz input. The audited CLAP and BioLingual mel frontends stop at **14 kHz**, even though their waveforms are sampled at 48 kHz. This is checkpoint-specific, not a universal property of everything named CLAP. Simply raising the sample rate argument or mel limit does not make existing weights validated high-frequency models. OpenWhistle's 44.1 kHz model also cannot retain the entire bandwidth of its 96 kHz source recordings. [CLAP config](https://huggingface.co/laion/clap-htsat-unfused/blob/main/preprocessor_config.json), [BioLingual config](https://huggingface.co/davidrrobinson/BioLingual/blob/main/preprocessor_config.json), [OpenWhistle card](https://huggingface.co/dolphinteam/OpenWhistle-Wav2Vec2.0).

For the project, retain original-rate audio and provenance. Produce a separate model-compatible copy. Inspect spectrograms before downsampling; log any pitch shifting or slowing used for human listening. Those transformations can be artistic choices but alter the evidence given to a pretrained model. Broadband echolocation clicks deserve special care: a good embedding of a filtered recording is not a complete description of the original signal.

## Four workable audio-to-image paths

These are proposed engineering and artistic designs, not biological interpretations:

1. **Acoustic controls → shape.** Map whistle time-frequency contours to curves, slopes to curvature, harmonics to parallel strands, amplitude to stroke width; map coda click times to points, intervals to spacing and repeated patterns to repetitions. Keep absolute-frequency and normalized-shape views so normalization remains visible. Deterministic geometry is easy to reproduce and does not require a generator.
2. **Embeddings → artist-defined controls or prompts.** Cluster OpenWhistle/AVES/CLAP features, reduce dimensions with PCA and let Livia assign visual properties to trajectories or clusters. Alternatively score a small dictionary of acoustic descriptions with CLAP/BioLingual, then construct an image prompt from the chosen descriptors plus her vocabulary. Scores compare supplied candidates; they are not measured emotions or a free-text transcription.
3. **ImageBind → retrieval / visual selection.** Embed a curated set of Livia's images and query it using audio. That model deliberately aligns modalities; underwater audio still presents an unvalidated domain shift, and its 16 kHz frontend loses higher frequencies. Selection can feed an image-to-image editor afterward, with Livia defining the transformation.
4. **Train an adapter → image-generator conditioning.** Build paired sound/visual examples or artist-selected target controls, freeze the audio encoder and initially train only a small projection/control network. Evaluate whether changing a recording changes the intended visual property consistently. This learns a chosen aesthetic correspondence; it does not discover an animal's intended image.

CLAP is **not a drop-in CLIP replacement**. CLAP aligns audio and text within its own learned space; CLIP aligns images and text within another. Even matching vector dimensions would not align those coordinates. Image diffusion systems may require token-level text states or generator-specific image features, not a single CLAP vector. Direct conditioning therefore needs a compatible decoder/adapter and a training objective, or an explicit text-mediated route. ImageBind improves cross-modal alignment but its released checkpoint is still an encoder. [CLAP architecture](https://github.com/LAION-AI/CLAP), [ImageBind architecture and retrieval demo](https://github.com/facebookresearch/ImageBind).

## Prioritized exploration

1. **Begin with annotated contours and coda timing, plus a small original-rate sample set.** Make one reproducible contour-to-form artwork with visible metadata and no inferred meaning.
2. **Compare OpenWhistle embeddings with a simple acoustic-feature baseline for dolphins**, after resolving the model license for the intended use. For general audible similarity, add the Apache-2.0 HF CLAP checkpoint; test recording-session leakage before assigning cluster interpretations.
3. **Try a single DoLittle checkpoint if generated sound is part of the artwork.** The 32k checkpoint offers a useful 42-second window and fewer download bytes than the 10k model; start with a short continuation rather than the 128k context.
4. **Use WhAM for coda generation only after evaluating the noncommercial/no-derivatives weight terms.** Its published social-unit results do not make the relevant annotations available in the public audio pack.
5. **Keep ImageBind and larger captioning models optional.** A useful extra embedding baseline is **Perch 2.0**: Google's cetacean transfer study tests it on underwater datasets despite terrestrial pretraining; use current [Hoplite inference tooling](https://github.com/google-research/hoplite), rather than assuming the older research repository installs cleanly. [Google's underwater evaluation](https://www.research.google/blog/how-ai-trained-on-birds-is-surfacing-underwater-mysteries/). **NatureLM-audio** generates language answers/captions, not animal audio; its BEATs + Llama-3.1-8B stack and CC BY-NC-SA model license make it a later optional experiment. [Official model card](https://huggingface.co/EarthSpeciesProject/NatureLM-audio).

No additional ready-to-run dolphin-specific audio generator was verified in this audit. The residency proposal can accurately describe “visual forms shaped by cetacean acoustic structure and documented social context,” while treating machine-generated sound and aesthetic mappings as explicit artistic interventions.
